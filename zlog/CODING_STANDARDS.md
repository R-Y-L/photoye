# Photoye 工程开发规范与代码准则

> **生效版本:** 3.0  
> **适用范围:** Photoye 全仓库代码设计、编写、审查与重构

---

## 1. 变更控制与受控原则
- **优先代码复用**：实现新功能前，先全面通读已有模块（`models/`, `database.py`, `analyzer.py` 等），最大化复用现有类、工具函数与数据接口。
- **重大改动申报**：修改数据库核心表结构、重构底层推理流水线、变更现有公共 API 签名或增设核心模块前，先提交变更方案与改动点清单，经确认后实施。
- **精准交付**：仅编写需求规格直接规定的逻辑，保持代码库精炼纯粹。

## 2. 表达与注释规范
- **正向表达**：函数命名、条件分支与文档说明使用肯定语气。优先使用 `is_valid`、`is_ready`、`if enabled:`，保持逻辑清晰直观。
- **现行决策驱动**：注释与文档直接阐明当前技术方案的选型理由、业务逻辑与不变式，聚焦于现行代码的优势与预期行为。
- **风格一致性**：保持代码与所属模块现有的命名规范、类型注解与格式风格一致。

## 3. 架构与依赖原则
- **统一轻量运行时**：全栈依赖纯 Python 与 ONNX Runtime，保持各系统平台零外部编译、开箱即用。
- **全新设计，轻装上阵**：开发阶段直接采用 V3.0 最新定义的数据结构与接口，专注于当前业务闭环的高效实现。
- **分层解耦**：核心业务计算（AI 推理、分拣引擎、台账逻辑）与 PyQt6 界面表现层保持解耦，业务层提供独立自动化单测能力。

## 4.阶段性提交
- **健康的git存档**：阶段性小任务完成即提供准确描述的git提交提示词，维持代码记录的完善与可回溯性。
